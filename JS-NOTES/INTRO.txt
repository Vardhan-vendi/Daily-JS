ECMASCRIPT vs JAVASCRIPT:---
------------------------

- ECMAscript is a blueprint/specification that defines the rules for javascript ,includes 
            -- variables
            -- data types
            -- operators
            -- functions
            -- objects
            -- classes
            -- modules
            -- iterators
            -- promises
        - defines core features and behaviours

- JAVASCRIPT is the actual implementation of ECMASCRIPT specification
        -- js also provides the API's (not part of ECMAScript ) such as
            . DOM API
            . Fetch API
            . local storage API
            . browser API
            . node.js API




ways to write JavaScripts

    Inline Javascript :- - we write js directly inside the html tags , using HTML event attributes 
                           like onClick,OnFoucs.
                        - <button onclick="console.log('hello vardhan')">click me.!</button>
    internal JS        :- - we create JS  inside the Script tags
                        - place of script tag effects the execution

                                . html parsing starts from top to button from head tag.
                                . if script tag found first it executes then even the DOM not found.
                                so placing the Script at the end is prefered.

    external JS : --we write the .js file and link it using the <script src = "file.ext"><script/>


    Script loading: normal, defer and async
    --------------------------------------

    normal : stops the parsing html,  and js is downloaded and executed 
          <head> 
            <script src ="index.js"><script/>
            <body><body/>
          <head/>
    defer : continues parsing html and in parallel it downloads the js ,once the html parsing 
            completed successfully then only executes the JS.

            <head> 
                <script src ="index.js" defer ><script/>
                <body><body/>
            <head/>


    async : continues parsing html and in parallel it downloads the js ,once the JS is 
            ,immediately executes the JS stopping  html parsing 
              <head> 
                <script src ="index.js" async ><script/>
                <body><body/>
            <head/>
            
Note : we see difference in DOM operations


variables: let vs var vs const
----------------------------
- variable is a name given to the memory location, where we can store the data .
- with the help of that variable , we can access the data.
- 3 ways to create the variable in JS 

  1. using var :
  ***************
  --> var is the older wy to create the variable
  --> syntax :  var var_name = value;
	eg :- var name,var age = 20;
  --> when using 'var' we can redeclare the same variable n number of times
  
		var a = 100;
		var a = 200;/// no error when using var
  --> in below 
			'''console.log(a)//undefined 
			   var a = 100
			'''
			
		In var , we can access the variable even before the declaration , through the concept of Hoisting
		
		Internally ,it becomes 
			'''	
				var a
				console.log(a)/// undefined
				a= 100
			'''
		in hoisting only the declaration is hoisted, not the assignment.

    --> var has the function scope not block scope ..
				'''
					function fun(){
						if(true){
						
							var message = "hello";
						}
						console.log(message);// 'hello'
					}
				'''
				
		problems of var :
		 + redeclaration
		 + can access before declaration
		 + having function scope
	2. let usage :
		--> to overcome the drwbacks in var, let is introduced in the ES6 
		--> Does not allow the variable redeclaration.but we can redeclaration same varible with different scope
		-->whenever we try to access the varible before declaration, even though the variable is hosited ,but it be stored in TEMPERAL DEAD ZONE(TDZ) ,until its variable declartion is validated ,it can be accessed.
		--> does not allow the redeclaration of the already declared variable.
				ERROR : Cannot redeclare block-scoped variable 'name'.
				
		--> it has block scope
		--> Redeclaring let in the same scope is a " SyntaxError".
			'''
				function fun2(){
					let name ;
					if(true){
						let name = 'hi'//block- level variable
						console.log(name);
					}
					console.log(name)/// function level // undefined
				}
			'''
		
	3. const usage :
		--> used to store the constant values
				const PI = 3.14;
		--> it has 
			- initilization is mandatory at the time of declaration.
			- prevent reassignment
			- prevent redeclaration
			- block scope
			
		const with object :
		'''
			const info = {
				name : 'vardhan',
				age : 100
			}
			
			info.name = 'vendi vardhan' 
		'''
		
		it is valid ,const prevent the reassignment, not obj modifications
